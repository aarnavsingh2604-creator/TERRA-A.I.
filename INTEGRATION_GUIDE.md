
### NASA imagery discovery
GET `http://127.0.0.1:5001/api/imagery/search?target=Mars&q=Atacama%20Desert&page_size=10`
This is an imagery discovery search, not a promise that each result is calibrated/georeferenced satellite data.

### CLIP semantic matching
POST `http://127.0.0.1:5001/api/clip/score`
```json
{
  "target": "Mars",
  "image_path": "data/images/your_image.jpg"
}
```
The CLIP model is downloaded on first use. Similarity is not a probability or a scientific analog score.

### Generate candidate CSV
POST `http://127.0.0.1:5001/api/candidates/generate`
```json
{
  "target": "Mars",
  "candidates": [
    {
      "site_id": "TA-101",
      "site_name": "Atacama test candidate",
      "country": "Chile",
      "latitude": -23.5,
      "longitude": -68.2,
      "visual_similarity": 81.5
    }
  ]
}
```
This writes `data/candidates.csv` using the exact columns your current frontend expects.

## Two small frontend fixes required

Your uploaded `app.py` currently has a typo in the score explanation:
```python
f"- {SCORE_LABELS[key]}: **{weightpip:.0%}**"
```
Change `weightpip` to `weight`.

Your current `load_data()` fills missing scientific scores with zero:
```python
df[col] = pd.to_numeric(df[col], errors="coerce").fillna(0).clip(0, 100)
```
For discovery-only records, that wrongly turns "not measured yet" into a score of zero. Change it to preserve missing values:
```python
df[col] = pd.to_numeric(df[col], errors="coerce").clip(0, 100)
```
Then calculate a weighted score using only available dimensions and renormalize their weights:
```python
def available_weighted_score(row, weights):
    available = {k: w for k, w in weights.items() if pd.notna(row[k])}
    total = sum(available.values())
    if total == 0:
        return float("nan")
    return sum(row[k] * w for k, w in available.items()) / total

df["analog_score"] = df.apply(
    lambda row: available_weighted_score(row, weights), axis=1
)
```
Also, `data_coverage` should reflect availability of actual dimension data, not suitability. In this first backend phase only the visual dimension may be present, so coverage can be 20%. Your current default minimum coverage of 50% will hide such discovery-only candidates. Temporarily set the slider default to 0, or wait until Developer 2 supplies the other dimensions.

The current dashboard's objective weights are already mission/objective-specific. Keep that frontend logic as the display/ranking layer only after the relevant scientific scores are populated. Do not use CLIP similarity as a substitute for terrain, geology, climate or water scores.
